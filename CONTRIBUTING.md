# Участие в разработке

Спасибо за интерес к «ТСН: Управление посёлком». До отправки изменений ознакомьтесь с `README.md`, а о потенциальных уязвимостях сообщайте по процедуре из `SECURITY.md`, не через публичные issue.

## Локальная проверка

Нужны Node.js 22+, npm 10+ и Docker Compose для сценариев с PostgreSQL.

```bash
npm ci
npm run verify
```

Для разработки с базой данных:

```bash
cp .env.example .env
docker compose up -d
npm run db:generate
npm run db:migrate -- --name describe-change
npm run db:seed
npm run dev:api
```

В отдельном терминале запустите `npm run dev`.

## Правила изменений

- Создавайте небольшую ветку от актуальной `main` и один pull request на одну законченную задачу.
- Не добавляйте `.env`, ключи, токены, выгрузки базы, пользовательские загрузки или персональные данные.
- Проверяйте права на сервере; скрытие кнопки в интерфейсе не является контролем доступа.
- Изменяйте схему Prisma только новой накопительной миграцией. Не переписывайте уже опубликованные миграции.
- Добавляйте сфокусированные тесты для бизнес-правил и обновляйте документацию вместе с поведением.
- Не создавайте release-теги из pull request: версию выпускает сопровождающий после слияния.

## Pull request

В описании укажите результат, способ проверки, риски для ролей и данных, а также порядок отката. Pull request готов к рассмотрению после успешного `npm run verify` и проверок GitHub Actions.
