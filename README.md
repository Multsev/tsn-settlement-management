# Прозор

Адаптивный MVP-прототип личного кабинета жителя коттеджного поселка / ТСН. Он воплощает главный сценарий ТЗ: за пару минут увидеть работы, деньги и действия, требующие внимания.

## Запуск интерфейса

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Vite выведет локальный адрес приложения. Для production-сборки используйте `npm run build`; для проверок — `npm test` или полную проверку `npm run verify`.

## Backend и база данных

Требуются Docker Desktop и Node.js 22+. Скопируйте настройки и поднимите PostgreSQL:

```bash
cp .env.example .env
docker compose up -d
npm install
npm run db:generate
npm run db:migrate -- --name initial
npm run db:seed
npm run dev:api
```

API откроется по `http://localhost:3000`; проверка доступности — `GET /api/health`. Демо-житель: `alexander@example.test`, демо-председатель: `chairman@example.test`, общий пароль `ChangeMe123!`, идентификатор поселка `novotitarovka`. Эти учетные данные предназначены только для локальной разработки.

Запустите интерфейс в отдельном терминале командой `npm run dev`. Экран входа отправляет данные в API, сохраняет JWT только в `sessionStorage` браузера и загружает dashboard, проекты и заявки из PostgreSQL. При необходимости укажите другой адрес API через `VITE_API_URL` и разрешите адрес интерфейса переменной `WEB_ORIGIN`.

Авторизация: `POST /api/auth/login` с JSON `{ "email", "password", "communitySlug" }`. Возвращаемый JWT нужно передавать как `Authorization: Bearer <token>` для `/api/dashboard`, `/api/projects` и `/api/issues`.

## Что реализовано

- Dashboard жителя: актуальные работы, важное объявление, персональные действия и финансовая сводка.
- Разделы проектов, финансов, заявок и документов.
- Карточка проекта с прозрачной связью бюджет → траты → готовность → последнее обновление.
- Создание демонстрационной заявки; навигация и модальные карточки работают без сервера.
- Mobile-first интерфейс с нижней навигацией на смартфонах.

## Инициативы, голосования и права

В MVP голосование является информационным: оно служит обязательным продуктовым фильтром перед созданием проекта, но не заменяет юридически значимое общее собрание ТСН.

| Роль | Возможности |
| --- | --- |
| `resident` / `owner` | Предложить инициативу, просматривать инициативы и голосовать один раз. |
| `assistant_chairman` | Взять инициативу в проработку, готовить материалы. |
| `board_member` | Просматривать и прорабатывать инициативы. |
| `chairman` | Открывать голосование, задавать пороги, после успешного голосования создавать проект и управлять бюджетом. |
| `administrator` | Техническое управление, имеет те же операционные права, что и председатель. |

Проект нельзя создать прямым запросом. Путь всегда один: `инициатива → голосование → завершение срока → кворум + поддержка → проект`. При открытии голосования система фиксирует количество допущенных участников, поэтому последующие изменения состава не меняют кворум. По умолчанию требуется 30% участия и 60% голосов «за» среди проголосовавших; председатель указывает пороги при запуске в пределах 1–100%.

## Соседский каталог и доска услуг

У подтвержденного участника есть профиль навыков — например, «массаж», «ремонт компьютеров», «репетиторство». Житель может включить видимость профиля и по отдельности дать согласие на показ телефона и email. По умолчанию все это выключено.

Каталог возвращает только имя, публичные навыки и улицу без номера участка. Контакты возвращаются строго по настройкам владельца. API поддерживает поиск `GET /api/directory?skill=компьютер&street=Калинина`, а доска объявлений — `GET`/`POST /api/listings`; объявления бывают `OFFER` (предлагаю) и `REQUEST` (ищу). Объявление может закрыть автор либо председатель/администратор.

Перед использованием выполните миграцию:

```bash
npm run db:migrate -- --name add-neighbor-directory-and-listings
```

## О поселке

Раздел «О поселке» объединяет адрес, контакты обслуживающих организаций, стартовые инструкции для нового собственника, FAQ, правила и ссылки на уставные документы. Председатель или помощник председателя публикует эти сведения через `/api/community-info`; житель видит только опубликованные материалы.

## Финансы

`GET /api/finances/me` показывает жителю только его начисления и платежи. Председатель, правление и администратор получают агрегированную сводку через `GET /api/finances/summary`; создавать начисления и расходы могут только председатель и администратор. Расход допускает ссылку на проект и увеличивает его фактически потраченную сумму.

Финансовый скоуп закрывает полный ручной учет MVP: личную историю начислений и оплат, агрегированную сводку, реестр расходов, связь расхода с проектом, целевые сборы и добровольные взносы. В кабинете председателя доступны формы начисления, регистрации оплаты, расхода и открытия сбора. Автоматическая банковская сверка и интернет-эквайринг не входят в MVP.

```bash
npm run db:migrate -- --name complete-financial-scope
```

```bash
npm run db:migrate -- --name add-community-information-center
```

## Улицы, участки и обращения

Раздел «Улицы и участки» содержит паспорта улиц: состояние дороги, покрытие освещением, количество участков, заселение, собираемость начислений и число активных обращений. Председатель ведет реестр улиц и участков. Житель может запросить привязку свободного участка, а председатель — подтвердить или отклонить заявку; только после подтверждения участок связывается с аккаунтом.

Обращения проходят контролируемый цикл `новая → принята → запланирована/в работе → выполнена → закрыта`. Правление назначает ответственного и срок, а завершение требует описания результата и ссылки на фото после работ. Все изменения статуса сохраняются в истории обращения.

```bash
npm run db:migrate -- --name complete-streets-properties-issues-scope
```

## Проекты, задачи и дорожная карта

Проект создается только из инициативы после завершенного голосования с достигнутыми порогами. Председатель управляет улицей или территорией проекта, приоритетом, ответственным, сроками, бюджетом и источником финансирования. Члены правления могут добавлять задачи, менять их рабочий статус и публиковать обновления с готовностью и фотографией.

Статус проекта меняется только по допустимому маршруту `идея → оценка → запланировано/сбор средств → в работе → завершено`. Завершение требует закрыть все задачи, описать результат и приложить ссылку на фото после работ. Экран «Дорожная карта» группирует проекты по годам и кварталам, а панель председателя показывает просроченные проекты, задачи и карточки без обновлений более 14 дней.

```bash
npm run db:migrate -- --name complete-projects-tasks-roadmap-scope
```

## Решения, документы и подрядчики

Реестр решений хранит основание, тип, дату, кем принято решение, процент поддержки, связанные проекты и статус исполнения. Решение проходит контролируемый маршрут `принято → исполняется → исполнено`; завершение требует текстового результата. Все изменения журналируются.

Центральное хранилище документов поддерживает уставы, протоколы, регламенты, договоры, планы, сметы, счета, акты, письма и ответы организаций. Один документ можно связать с проектом, решением, расходом и подрядчиком. В MVP хранится проверяемая `http(s)`-ссылка; загрузка в S3-совместимое хранилище остается инфраструктурным продолжением.

Карточка подрядчика содержит контакты, виды работ, оценку и историю сотрудничества. Связь с проектом фиксирует роль, номер и стоимость договора, а также срок гарантии. Проект показывает связанные решения, документы и подрядчиков в своей подробной карточке.

```bash
npm run db:migrate -- --name complete-decisions-documents-contractors-scope
```

## Объявления, уведомления и еженедельный дайджест

Председатель и администратор публикуют обычные, важные и аварийные объявления с датой начала и сроком действия. Активная публикация появляется на главной и в общем реестре. Житель получает персональный центр уведомлений, отмечает сообщения прочитанными и выбирает уровень внимания: только важное, важное с обновлениями проектов или все сообщения.

Дайджест собирает результаты завершенных обращений, обновления проектов, поступления, число активных проектов, открытые голосования и требуемые действия за календарную неделю. Правление формирует черновик, а председатель публикует его жителям. Фоновая задача готовит черновик по понедельникам и не публикует его без решения председателя.

Внутренние уведомления работают сразу. Для email используется надежная очередь: без провайдера письма остаются в статусе `PENDING`, а при настройке `EMAIL_WEBHOOK_URL` сервер отправляет провайдеру JSON `{ to, subject, text }` и повторяет неудачную доставку до трех раз. Необязательный `EMAIL_WEBHOOK_TOKEN` передается как Bearer-токен.

```bash
npm run db:migrate -- --name complete-announcements-notifications-digest-scope
```

## Пользователи, роли и управление доступом

Председатель ведет реестр участников, видит привязанные участки, приглашает новых жителей и назначает роли в пределах своих полномочий. Приглашение содержит одноразовый токен, хранится только в виде SHA-256-хеша и действует семь дней. Новый участник задает собственный пароль и получает доступ после принятия приглашения.

Доступ можно подтвердить или приостановить; заблокированная учетная запись немедленно перестает проходить backend-проверку. Председатель не может назначить системного администратора, изменить собственные права или убрать последнего активного председателя. Пользователь с членством в нескольких поселках переключает контекст без повторного ввода пароля, получая новый JWT для выбранного поселка.

```bash
npm run db:migrate -- --name complete-users-roles-access-scope
```

## Интерактивная карта поселка

Карта объединяет инфраструктуру, участки, активные проекты и проблемные точки. Житель включает и выключает слои, выбирает маркер и открывает безопасную карточку объекта; данные владельцев участка в картографический API не попадают. Обращение можно создать сразу с географической точкой.

Председатель размещает въезды, дороги, камеры, освещение, площадки и коммуникации, а также назначает координаты участкам, проектам и обращениям. Геоданные хранятся независимо от картографического поставщика, поэтому визуальный слой можно переключить на OpenStreetMap или корпоративные тайлы без миграции доменных сущностей.

```bash
npm run db:migrate -- --name complete-interactive-map-scope
```

## Структура

- `index.html` — единственная точка подключения приложения.
- `src/main.js` — запуск, рендер экранов и UI-события.
- `src/data.js` — демонстрационные доменные данные и форматирование денег. При подключении API замените этот модуль репозиториями запросов.
- `src/styles.css` — адаптивная дизайн-система и все стили.
- `src/api.js` и `src/session.js` — единый HTTP-клиент и временное хранение сессии браузера.
- `src/project-views.js` — дорожная карта, проектная панель и подробная карточка проекта.
- `src/governance-views.js` — реестры решений, документов и подрядчиков, а также их рабочие формы.
- `src/communications-views.js` — объявления, дайджест, центр и настройки уведомлений.
- `src/member-views.js` — реестр участников, приглашения и формы управления доступом.
- `src/map-views.js` — интерактивные слои карты и карточки объектов территории.
- `server/` — Express API: auth, RBAC-мидлварь, журналы аудита и маршруты MVP.
- `server/background-jobs.js` — подготовка еженедельного дайджеста и обработка email-очереди.
- `prisma/schema.prisma` — PostgreSQL-схема, включающая поселки, членство, участки, проекты, заявки и финансы.
- `prisma/seed.js` — безопасный для повторного запуска набор локальных демо-данных.
- `docker-compose.yml` — локальный PostgreSQL.
- `tests/` — быстрые проверки доменных данных.
- `.github/workflows/` — CI при изменении `main` и публикация GitHub Release при push тега.
- `scripts/release-guide.md` — правила версий и точные команды релиза.

## Версии и релизы

Проект использует Semantic Versioning. После завершения обновления выберите тип изменения и выполните одну команду:

```bash
npm run release:patch  # исправление
npm run release:minor  # новая совместимая функция
npm run release:major  # несовместимое изменение
git push origin main --follow-tags
```

Команда релиза автоматически выполняет тесты и production-сборку, меняет версию, создаёт коммит `release: vX.Y.Z` и тег. GitHub Actions опубликует GitHub Release при поступлении тега. Более подробные правила — в `scripts/release-guide.md`.

## Как безопасно развивать

Следующим шагом подключите REST API: вынесите загрузку каждого ресурса из `src/data.js` в отдельный модуль, например `src/api/projects.js`, сохранив форму объектов, которую используют экраны. API уже ограничивает данные по `communityId` и RBAC; UI не должен быть единственным уровнем проверки доступа.
