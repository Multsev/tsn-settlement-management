# Подготовка первого размещения на GitHub

## 1. Решение владельца перед публикацией

Выберите режим распространения кода. Без файла `LICENSE` посетители могут читать публичный репозиторий, но не получают разрешения свободно копировать, изменять и распространять код. Добавлять MIT, Apache-2.0 или другую лицензию следует только после явного решения владельца и проверки прав на весь включенный материал.

Убедитесь, что демонстрационные данные вымышлены, а техническое задание и документы из `docs/` разрешено публиковать.

## 2. Локальная проверка

```bash
npm ci
npm run verify
git status --short
```

Ожидаемый результат: тесты, сборка, Prisma-схема, production-артефакты и GitHub readiness проходят; рабочее дерево чистое после коммита.

## 3. Создание репозитория

Создайте на GitHub пустой репозиторий без автоматически сгенерированных README, `.gitignore` и лицензии. Затем подключите его:

```bash
git remote add origin git@github.com:OWNER/REPOSITORY.git
git remote -v
git push -u origin main
```

При первом push не используйте `--follow-tags`: в локальной истории есть много версионных тегов, и каждый отправленный тег `v*` запускает публикацию GitHub Release. Если нужен только текущий релиз, отправьте его отдельно:

```bash
git push origin "$(git describe --tags --abbrev=0)"
```

Для последующих релизов используйте обычный процесс из `scripts/release-guide.md`.

## 4. Настройки GitHub

- Сделайте `main` защищенной веткой и запретите прямой push без pull request.
- Требуйте успешную проверку **Тесты и сборка** перед слиянием.
- Включите secret scanning и push protection, Dependabot alerts и security updates.
- Разрешите приватные сообщения об уязвимостях в разделе Security.
- Запретите force push и удаление `main`.
- Добавьте краткое описание проекта и темы `tsn`, `hoa`, `community-management`, `vite`, `express`, `prisma`, `postgresql`, `pwa`.

## 5. Контроль после публикации

Проверьте вкладки Actions и Security, откройте README как новый посетитель и убедитесь, что в истории, релизах и артефактах нет секретов или персональных данных. Production-развертывание выполняйте только по `docs/production.md` с новым случайным секретом и HTTPS.
