# Правила версий и релизов

Версия соответствует [Semantic Versioning](https://semver.org/lang/ru/):

- `patch` (`0.1.1`) — исправление без изменения совместимого поведения;
- `minor` (`0.2.0`) — новая функция, совместимая с предыдущей версией;
- `major` (`1.0.0`) — несовместимое изменение.

Перед релизом рабочее дерево должно быть чистым. Команды `npm run release:*` сначала выполняют тесты и production-сборку, затем обновляют `package.json` и `package-lock.json`, создают Git-коммит и аннотированный тег `vX.Y.Z`.

```bash
npm run release:patch
git push origin main --follow-tags
```

Для функционального обновления замените `patch` на `minor`. GitHub Actions перезапустит проверки на `main`; при поступлении тега создаст GitHub Release с автоматически сгенерированными заметками.

Не создавайте тег вручную: используйте одну из команд `release:*`, чтобы версия в теге совпадала с версией приложения.
